# Optimatech Sales Agent

وكيل مبيعات بالذكاء الاصطناعي لـ **Optimatech** — بيشتغل على **واتساب** و**فيسبوك ماسنجر**، بيرد على العملاء المحتملين بالعربي والإنجليزي، بيأهّلهم، **بيحجز مكالمات فعليًا في كالندر الفريق**، وبيسلّمهم لموظف بشري.

خدمة مستقلة (FastAPI + Celery + PostgreSQL/pgvector + Azure OpenAI). بتتكلم مع موقع Optimatech عن طريق HTTP بس.

---

## بيبيع إيه

الباقات الحقيقية، متطابقة مع `lib/services.ts` في الموقع:

| الباقة | سعر البداية |
|---|---|
| موقع تسويقي ثنائي اللغة | 11,900 ج |
| لوحة تحكم + CMS مخصص | 29,900 ج ⭐ الأكثر طلبًا |
| مساعد ذكي وأتمتة | 13,900 ج |
| إعداد Google Workspace | 3,500 ج |
| دفعة/فاتورة مخصصة | 500 – 1,000,000 ج |

**كل رقم بيطلع من الوكيل موصوف إنه سعر بداية**، والنطاق النهائي بيتأكد كتابةً بعد مكالمة. الجملة دي جوه الـ data نفسها (`price_is_starting_point`) مش في الـ prompt بس — فالموديل ميقدرش يسيبها.

> **الأسعار مبتتكتبش في قاعدة المعرفة.** لو حطيت رقم في مستند، بيبوظ في صمت والوكيل يفضل يقوله بثقة. فيه اختبار بيرفض أي رقم في المستندات المبدئية.

## اللي الوكيل بيعمله

### ١. Inbound — يرد ويأهّل
عميل بيبعت على واتساب أو ماسنجر → الوكيل بيرد بلغته، بيجاوب من قاعدة معرفة الشركة (RAG على pgvector)، بيرشّح الباقة اللي تناسب اللي وصفه، ويجمع التأهيل — سؤال واحد في المرة:

الاحتياج · نوع الجهة (شركة صغيرة / جمعية / ستارتاب / مركز تدريب) · حجمها · **بيستخدموا إيه دلوقتي** (Excel؟ موقع قديم؟ واتساب؟ ولا حاجة؟) · التوقيت · مين بياخد القرار · الميزانية لو قالها

الفرق بين اللي مستخدمينه دلوقتي واللي عايزينه هو المحادثة كلها.

### ٢. حجز مكالمات حقيقي
تلات أنواع مكالمات: تعارف مجانية (٢٠ د) · استشارة تقنية (٤٥ د) · بدء مشروع (٦٠ د).

الوكيل **بيشوف المواعيد الفاضية الحقيقية** ويحجز — العميل بياخد دعوة كالندر وMeet link وإيميل تأكيد. المكالمة المجانية هي العرض الافتراضي لأن النطاق بيكون لسه مش واضح غالبًا.

### ٣. Outbound — يجيب عملاء بالطرق المسموحة
- **Comment-to-DM:** أي تعليق على بوست أو إعلان → رد خاص واحد مسموح من Meta. أقوى مصدر محادثات حقيقي.
- **Facebook Lead Ads:** فورم اتقدّم → الوكيل يجيب بياناته ويبعت أول رسالة على واتساب بـ template معتمد.
- **Click-to-WhatsApp:** بيتسجّل الإعلان اللي جاب المحادثة، فتعرف أي creative بيجيب عملاء فعلًا.
- **Cadences:** متابعة على خطوات للـ leads اللي عملوا opt-in، بتتوقف فورًا أول ما العميل يرد.

### ٤. Cross-sell للعملاء الحاليين
عميل خلّص موقع → الخطوة الطبيعية لوحة تحكم يدير بيها المحتوى والسجلات. الوكيل بيقترح **بعد التسليم بس**، وبعد فترة استقرار، ومش بيقترح حاجة عنده. ولو العميل هو اللي سأل، ده بيتخطّى كل الشروط دي.

الجمهور هنا **عملاء بيدفعوا**، فالبوابة أكثر تحفظًا من ناحية الـ leads بشكل مقصود: عرض في وقت غلط على lead بيضيّع lead، على عميل بيضيّع علاقة.

## ⚠️ الالتزام بسياسات Meta — مبني في الكود

الرسايل الجماعية الباردة **تحرق الرقم والصفحة**. الخدمة مبنية بحيث ده مايحصلش:

| القاعدة | التنفيذ |
|---|---|
| مفيش رسالة لحد ملوش أساس قانوني | `NO_CONSENT` — لازم بعت لنا، أو opt-in صريح، أو قدّم فورم |
| نافذة الـ 24 ساعة | جواها نص عادي · برّاها واتساب: template معتمد بس · برّاها ماسنجر: **مفيش**، بنستنى |
| Opt-out فوري ونهائي | كلمة واحدة (`stop` / `الغاء` / `مش عايز`...) توقف كل حاجة وتلغي أي cadence |
| Quiet hours | مفيش رسالة proactive بين ٩م و٩ص بتوقيت العميل |
| سقف | رسالة proactive واحدة/يوم، و٥ على مدى العمر (قابل للتعديل) |
| Lead ساكت ٣٠ يوم | `LEAD_DORMANT` — بنوقف التواصل خلاص. القواعد بتمنع template لجهة اتصال قديمة، ومن الجهات دي بييجي الـ spam reports اللي بتنزّل تقييم الرقم. رسايلنا إحنا **مبتتحسبش** حياة، وإلا الـ cadence بيعيّش نفسه |
| نطاق محدود | الوكيل بيرد على خدمات الشركة وأسعارها وشغلها والحجز **بس**. أي حاجة برّه كده بيرفضها في سطر ويرجّع الكلام. سياسة Meta من يناير ٢٠٢٦ بتمنع الـ chatbots العامة على WhatsApp Business API |
| كل رفض متسجّل | صف بـ `SKIPPED` و`skip_reason` — الرفض موثّق زي الإرسال |

الردود على اللي بيسأل **مش** بتتأثر بالـ quiet hours ولا بالسقوف. تأخير رد على سؤال حيّ خدمة أسوأ، مش التزام أحسن.

## المعمارية

```
Meta (WhatsApp / Messenger / Page)
        │  webhook (X-Hub-Signature-256)
        ▼
  FastAPI  /v1/sales/webhooks/*        ← السطح العام الوحيد
        │  Celery (Redis)
        ▼
  inbound.handle_event
        ├─ repository     → هوية العميل عبر القنوات + تسجيل الرسائل (idempotent)
        ├─ policy         → مسموح نرد؟ مسموح نبعت؟
        ├─ agent          → tool-calling loop محدود
        │     ├─ kb          → RAG على قاعدة معرفة المبيعات
        │     ├─ offerings   → الباقات والأسعار
        │     └─ booking     → ينده منطق الحجز في الموقع ← مش بيعيد حسابه
        ├─ qualification  → score حسابي + مرحلة
        └─ outbound       → queue + cadences (Celery beat)

  FastAPI  /v1/sales/*  (X-Internal-Api-Key)  ← لوحة الـ CRM
```

**قرارات تستاهل الانتباه:**

- **الحجز مش معمول من جديد.** الموقع بيحسب: التوفر − المحجوز − **تعارضات Google Calendar**، وبعدين بيعمل Meet link ويبعت إيميلين. الوكيل بينده `/api/internal/booking/*` بتاع الموقع. **منطق حجز واحد بس في السيستم كله** — ولو كتبته تاني كان هيحجز فوق اجتماعات موجودة في الكالندر بس.
- **أنواع `intern-*` مستحيل توصل لعميل.** دي مقابلات تدريب؛ الوكيل بيشوف `category = 'call'` بس.
- **الـ policy engine نقي** (`app/sales/policy.py`) — مفيهوش DB ولا HTTP، فكل قاعدة متغطّية باختبار.
- **الـ scoring حسابي مش موديل** — الـ rep يشوف ليه الـ lead واصل ٧٨، والرقم مايتغيرش لما الـ prompt يتعدّل.
- **الموديل ميقدرش يعدّل الـ stage ولا الـ score** (مشتقّين)، و`save_lead_details` ميقدرش يمسح بيانات معروفة. يضيف، مش يمسح.
- **التليفون مطلوب للحجز** — زي فورم الموقع بالظبط. مكالمة مفيش طريقة توصل صاحبها مش حجز، وplaceholder بيروح على دعوة كالندر حقيقية.

## التشغيل محليًا

```bash
cp .env.example .env      # واملأ القيم
docker compose up --build
```

بيقوم: Postgres (pgvector) + Redis + migrate + API على `:8000` + Celery worker + beat.

نزّل قاعدة المعرفة والـ cadences المبدئية:

```bash
curl -X POST http://localhost:8000/v1/sales/knowledge/seed \
  -H "X-Internal-Api-Key: $INTERNAL_API_KEY"
```

> ⚠️ المستندات المبدئية موصوفة بإنها **للمراجعة**، ومكتوبة من الـ product brief بتاع الموقع. لازم الفريق يقراها ويستبدلها — خصوصًا دراسات الحالة، اللي المفروض تسمّي عملاء حقيقيين.

جرّب الوكيل بدون أي ربط بـ Meta:

```bash
curl -X POST http://localhost:8000/v1/sales/preview/chat \
  -H "X-Internal-Api-Key: $INTERNAL_API_KEY" -H "Content-Type: application/json" \
  -d '{"session_id":"t1","message":"عايز موقع لشركتي، بكام؟"}'
```
